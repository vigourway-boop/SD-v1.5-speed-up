CSK4 data path:
- The PC removes the duplicate CFG batch.
- The PC applies 2x2 average pooling to 4 x 64 x 64 latent features.
- Each 4 x 32 x 32 feature is symmetrically quantized to 4096 int8 values.
- The per-step payload is 4096 bytes, 8x smaller than CSK2's 32768 bytes.
- The PYNQ ARM stores the dynamic-threshold controller state.
- The FPGA stores the reference feature in BRAM and controls all skip decisions.
- The FPGA requires both cosine and normalized-distance gates to pass.

Notes:
- The FPGA computes dot, norms, cosine-threshold decision, normalized-distance
  decision, warmup gating, consecutive-skip limiting, skip streak and reference updates.
- The PYNQ ARM handles transport, dynamic threshold scheduling, IP control and
  conversion of FPGA statistics into reported floating-point values.
- The CSK4 protocol intentionally rejects older CSK2/CSK3 clients and servers.
- Deploy the bitstream, HWH and server from the same artifact set.
- The bit and HWH files must use the same base filename in one directory.
- The command-line seed path was corrected so baseline hashes are identical
  across separate threshold runs using the same explicit seed.
- A corrected 3-seed x 3-threshold calibration found that 0.00035 had the best
  average candidate quality (1.729x speedup and 33.192 dB PSNR), but its worst
  seed reached only 23.747 dB PSNR.
- A stricter 0.00015 distance gate reduced that seed to 21 skips and 1.22x
  speedup but still reached only 24.455 dB PSNR. No distance threshold was
  promoted to the default; the skip policy needs trajectory-aware refinement.
